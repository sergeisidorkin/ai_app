# checklist-file-verify

Работай только внутри корня задачи. Один вызов = один комплект из сообщения пользователя. Не обходи весь inbox и не трогай другие комплекты.

Две фазы. Фаза названа в сообщении: `select` или `classify`. Другую фазу не выполняй.

Общие правила dest — как у сортировки:

- Класть можно только в папки, для которых есть строка в `requests.md`.
- `высокая` + конкретный пункт `CODE-NN` → `move`.
- Если после чтения выдержек уверенность **не стала высокой** — `confirm`, не `review`.
- `review` только у первой сортировки, до клика «Проверить».
- Если выдержки однозначно соответствуют **другой** строке `requests.md`, в том числе другого раздела — укажи её `dest`. Не оставляй комплект в текущей гипотезе из инерции.
- Не выдумывай цитаты: `quote` только дословный фрагмент колонки «Текст запроса».
- Не копируй и не перемещай файлы.

## Фаза select

Данные: `files.json` (пути, размеры, `skipped`), гипотеза dest, строки `requests.md` этого раздела.

1. Прочитай `files.json`. Не открывай файлы комплекта.
2. Выбери до трёх путей, которые отличают конкурирующие пункты dest (например декларация vs годовой отчёт, лицензия ИРД vs ПСД).
3. Не бери `skipped: true`, `.sig`, служебное.
4. Если один файл в списке — верни его.
5. Сразу JSON-объект, без таблицы:

```json
{"peek": ["ПД/Раздел ПД №0/ПЗ.pdf"], "reason": "титул ПЗ отличает ПСД от ИРД"}
```

Потом остановись.

## Фаза classify

Данные: `peek.md` (выдержки выбранных файлов) и `requests.md`.

1. Читай только эти два файла. Бинарники и весь комплект не открывай.
2. Сопоставь комплект с одной строкой пункта dest. Якорь может быть в другом разделе, чем текущая гипотеза.
3. JSON одного объекта, `kit` как в сообщении пользователя:

```json
{"kit":"Хвостохранилище/Декларация.pdf","files":1,"dest":"dest/01 TSF Хвостохранилище/TSF-05 Документы по безопасности","name":"Документы по безопасности","quote":"Декларация безопасности ГТС хвостохранилища","confidence":"высокая","action":"move"}
```

Если выдержки не повысили уверенность до высокой:

```json
{"kit":"Экономика/Договоры аффинажа/","files":2,"dest":"dest/02 LGL Право/LGL-09 Реестр договоров","name":"Реестр договоров","quote":"Реестр договоров с основными контрагентами","confidence":"средняя","action":"confirm"}
```

Если якорь в другом разделе, чем текущая гипотеза — всё равно укажи этот `dest`. Пример: гипотеза была PRC-15, выдержки про потребителей ЭЭ → INF-08:

```json
{"kit":"Переработка/Новые потребители ЭЭ ЗИФ 3,5/","files":2,"dest":"dest/08 INF Инфраструктура/INF-08 Потребители ЭЭ","name":"Потребители ЭЭ","quote":"Список потребителей электроэнергии, с указанием установленной мощности. Текущая мощность.","confidence":"высокая","action":"move"}
```

Если якоря мало и уверенность не стала высокой — `confidence` средняя или низкая, `action` `"confirm"`. Не возвращай `"review"`: это состояние до проверки. Не повышай уверенность по канцеляриту колонтитула без совпадения с текстом запроса.

Потом остановись.
